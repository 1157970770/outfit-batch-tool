# 妙搭部署与本地运行

> 适用对象：把 `miaoda/` 这套 React + NestJS 工程跑起来的人。
> 方案总览见 [../../docs/妙搭迁移方案.md](../../docs/妙搭迁移方案.md)。

## 1. 前置条件

| 项 | 要求 | 备注 |
| --- | --- | --- |
| Node.js | 22.x（本机 v22.22.2 验证过） | `node -v` |
| npm | 10.x | 本机 10.9.7；**不需要 pnpm**，workspaces 用 npm |
| 配置 | `server/web.json`、`server/config.json` | 缺 `session_secret` 会启动失败，先跑一次 `python run_web.py --init` |
| 数据 | `web-data-dev/`（开发）或 `web-data/`（生产） | 只读兼容现有目录，无需导入导出 |

## 2. 本地开发

```powershell
cd D:\批量视频任务设计区\miaoda
npm install --ignore-scripts       # 首次；--ignore-scripts 规避 Windows 沙箱的 postinstall EPERM
npm run dev                        # shared 编译 → 后端 3001 + 前端 5173
```

打开 <http://localhost:5173>，用现有 `server/web.json` 里的账号登录。

- 前端 vite 把 `/api`、`/healthz` 代理到 `http://127.0.0.1:3001`。
- 后端默认 `127.0.0.1:3001`、数据目录 `../web-data-dev`。
- 想换端口/数据目录：复制 `.env.example` 为 `.env` 再改，**不要**改 `server/web.json` 的 `port`（那是 Python 版在用的 8766）。

`.env` 支持的键：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `OUTFIT_SERVER_DIR` | `../server` | 配置目录（含 `web.json`/`config.json`/`imagegen.json`） |
| `OUTFIT_DATA_ROOT` | `web-data-dev` | 数据根；相对路径按**仓库根**解析 |
| `PORT` | `3001` | 后端端口 |
| `HOST` | `127.0.0.1` | 监听地址；局域网访问填 `0.0.0.0` |
| `OUTFIT_ALLOWED_HOSTS` | 自动探测 | 逗号分隔的 Host 白名单；设了就**不再**自动加本机网卡地址 |
| `MOCK_WAN` / `MOCK_WAN_BASE_URL` | `0` / `http://127.0.0.1:18090` | 联调 mock（P1 起生效） |

## 3. 生产构建

```powershell
cd miaoda
npm run build            # shared → server(nest build) → web(vite build)
npm run start            # node apps/server/dist/main.js
```

产物：

- `apps/web/dist/`：静态站点（`index.html` + `assets/*`），由后端托管并做 SPA 回退。
- `apps/server/dist/`：Nest 编译结果，入口 `dist/main.js`。

访问 `http://127.0.0.1:3001` 即可（不需要单独的 nginx）。若要前后端分开部署，把 `apps/web/dist` 交给静态托管，API 反向代理到 3001，并让 `/api` 与 `/healthz` 落到后端。

## 4. 上线到妙搭

妙搭工程按「一个 Web 服务 + 静态前端」组织时，按下表填：

| 配置项 | 值 |
| --- | --- |
| 构建命令 | `npm ci && npm run build`（若无 lockfile 变化用 `npm install`） |
| 启动命令 | `node apps/server/dist/main.js` |
| 服务端口 | `3001`（与 `PORT` 一致；平台若注入端口变量，用平台的） |
| 健康检查 | `GET /healthz` → `200 {"ok":true,...}` |
| 静态目录 | `apps/web/dist`（本项目由后端托管，平台侧无需再配） |
| 运行时 | Node 22 |
| 磁盘 | 需要持久卷挂载数据目录，见下 |

环境变量（妙搭控制台里配，覆盖 `.env`）：

```text
OUTFIT_SERVER_DIR=/app/server          # 配置目录，放 web.json / config.json / imagegen.json
OUTFIT_DATA_ROOT=/data/web-data        # 持久卷挂载点（jobs/batches/uploads/output/template_tags.json）
HOST=0.0.0.0
PORT=3001
OUTFIT_ALLOWED_HOSTS=<妙搭分配的域名>
```

> **必须先确认的三件事**（控制台的实际选项为准）：
> 1. 妙搭是否提供**持久磁盘**。没有的话 `jobs`/`uploads`/`output` 会在重启后丢失，只能当只读演示。
> 2. 是否会注入 `PORT`。若注入，`AppConfigService` 已优先读 `process.env.PORT`。
> 3. 是否只允许单实例。任务队列与标签写入都是**单进程**假设（和 Python 版一致），多实例会互相抢文件。

### 数据与配置怎么进去

- `server/web.json` 含密码哈希与会话密钥，`server/config.json` 含明文 API Key —— **不要提交到仓库**（`.gitignore` 已排除）。上线时用平台「密钥/环境变量 + 挂载配置文件」注入，或在容器启动脚本里从密钥服务写好再启动。
- 数据目录结构与 Python 版完全一致：`jobs/`、`batches/`、`uploads/`、`output/`、`logs/`、`ps/`、`imagegen/`、`tag_versions/`、`template_tags.json`、`manifest_overlay.json`。从现有机器迁移 = 停服 → 整目录复制 → 起服。

## 5. 自检清单（每次上线跑一遍）

```powershell
# 1) 健康检查
curl.exe -s http://<host>:3001/healthz

# 2) 一致性冒烟（默认打 3101，可传 base）
node scripts/parity.mjs http://<host>:3001

# 3) 页面
#    打开 / 应看到登录页；登录后顶栏显示账号与模板数；9 个 tab 可切换
```

`parity.mjs` 需要一对可登录账号：

```powershell
$env:PARITY_USER='你的账号'; $env:PARITY_PASS='你的密码'; node scripts/parity.mjs http://<host>:3001
```

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `spawn EPERM`（安装/构建时） | 受限沙箱禁止子进程管道；esbuild/npm postinstall 会中招 | 在普通终端跑，或 `npm install --ignore-scripts`；构建用非受限 shell |
| 启动报「缺少 session_secret」 | `server/web.json` 没初始化 | 先 `python run_web.py --init`，或手工写入 32 字节 base64url 的 `session_secret` |
| 登录 401「账号或密码不正确。」 | 账号不在当前 `OUTFIT_SERVER_DIR` 指向的 `web.json` | 确认 `OUTFIT_SERVER_DIR` 指对了目录 |
| 登录成功但刷新又回登录页 | Cookie 被跨站点丢弃（`SameSite=Lax`）或用了不同域名访问 | 用同一域名访问；HTTPS 下确认没有反向代理改写 `Set-Cookie` |
| 请求返回 421「访问地址无效。」 | Host 不在白名单 | 把访问域名加到 `OUTFIT_ALLOWED_HOSTS` |
| 请求返回 403「请求来源无效」 | 用 IP/别名访问但 Origin 不匹配 | 统一用同一个域名访问，别混用 IP 和主机名 |
| `/api/bootstrap` 里模板数明显不对 | 数据目录指错，或标签真源里 `missing/deprecated` 过多 | 看启动日志的「数据目录」，核对 `template_tags.json` |
| 页面 404 | 没跑 `npm run build`，`apps/web/dist` 不存在 | 构建后再 `npm start`，或开发时用 5173 |
| 自由视频上传参考视频时报「解析失败」/找不到 ffprobe | 容器里没有 `ffmpeg` | 镜像里装 ffmpeg，或设 `FFPROBE_PATH=/usr/bin/ffprobe`；只传图不需要它 |
| 自由视频报「参考视频/音频需要开启 COS 才能上传」 | 官方接口只接受 URL，不收 Base64 | 与 Python 版一致的行为；要在妙搭上跑通参考视频，需要先接 COS 适配器 |

## 7. 与 Python 版并存

两套可以同时跑，互不干扰（不同端口 + 不同数据目录时）：

- Python 版：8765（生产运行区）/ 8766（本机开发）。
- 妙搭版：3001（开发）/ 平台端口（线上）。

**同一个数据目录只能起一个进程**：`jobs`、`batches`、`imagegen` 都是「读 JSON → 写 JSON」的单进程模型。灰度期间建议妙搭版先读**副本**目录（例如 `web-data-miaoda/`，从 `web-data-dev` 复制），验证通过后再切生产。
