# 妙搭套壳部署（前端在妙搭，后端仍跑本机）

> 2026-11-11 方向调整：**只把前端搬到飞书妙搭，后端代码与运行保持现状**（本机 `python run_web.py`）。
> 原「NestJS 全量重写」方案（P0–P4 已完成）保留在 `miaoda/apps/server/`，作为可选/回退路径，不再作为主线。

## 1. 形态

```
浏览器 ──HTTPS──> 妙搭静态站点（miaoda/apps/web 构建产物）
                     │
                     └──HTTPS + Authorization: Bearer──> 本机 Python 服务（8765/8766）
```

- 前端只做 UI + 调接口，**没有服务端逻辑**；数据、任务、批次、标签真源全部还在本机。
- 本机服务新增一个**默认关闭**的跨域开关（`web.json → cors_origins`），不填时行为与以前完全一致。

## 2. 两个硬前提（缺一不可）

| 前提 | 原因 | 怎么解 |
| --- | --- | --- |
| 后端必须是 HTTPS | 妙搭页面是 HTTPS，请求 `http://192.168.10.179:8765` 会被浏览器按「混合内容」**直接拦掉**，连请求都发不出去 | 给本机服务套一层 HTTPS 入口：反向代理（Caddy/Nginx + 证书）、内网穿透（cloudflared / frp / 花生壳）、或公司统一的 HTTPS 网关 |
| 登录态走令牌 | 跨站请求浏览器不会带 `SameSite=Lax` 的 Cookie | 后端在跨域来源登录时额外返回 `token`，前端存起来用 `Authorization: Bearer` 带上（已实现） |

> 如果后端暂时没有 HTTPS：只能把前端也放回局域网 HTTP 访问（即继续用 Python 自带的 `static/`），妙搭这条路上不去。

## 3. 后端配置（本机，改完要重启）

`server/web.json` 增加一行（数组，可填多个来源）：

```json
"cors_origins": ["https://你的妙搭访问域名"]
```

- 域名取**浏览器地址栏里的 origin**（协议 + 域名 + 端口，结尾不要带 `/`），例如 `https://abc123.feishu.cn`。
- 填了以后：
  - 预检 `OPTIONS` 对这些来源回 204，并允许 `Authorization`、`X-File-Name`、`X-Tags`、`X-Auto-Number`、`X-Kind` 头；
  - 登录响应多一个 `token` 字段；
  - `Origin` 校验对这些来源放行（Host 白名单不受影响，仍要求访问的是本机地址）。
- 留空或不填 → 只接受同源请求，和历史上完全一样。

### 媒体文件怎么带令牌

`<img>`、`<video>`、`<a download>` 这三类标签**发不出 `Authorization` 头**，跨域时也带不上 Cookie。前端的 `mediaUrl()` 在套壳模式下会给自己的接口地址追加 `?access_token=<token>`（COS 签名链接原样不加），后端的 `_token()` 按「Cookie → `Authorization` → `?access_token=`」的顺序取。只有跨域白名单来源会用到这个参数，同源请求不多发任何东西。

> 令牌在 URL 里会进浏览器历史与本机访问日志；本服务的响应头已带 `Referrer-Policy: no-referrer`，不会随外链泄漏。

重启（设计区）：停止 `run_web.py` 再启动；生产区按 `启动器\重启网页服务-管理员.bat` 操作。
**重启会打断 running 任务**，先看 `web-data*/jobs/*.json` 有没有未完成的。

自检：

```bash
curl -i -X OPTIONS https://你的后端/api/me \
  -H "Origin: https://你的妙搭域名" \
  -H "Access-Control-Request-Method: GET"
# 期望 204，且响应头含 Access-Control-Allow-Origin: https://你的妙搭域名
```

## 4. 构建前端

```bash
cd miaoda
npm install                     # 首次（沙箱里要加 --ignore-scripts）
npm run build:shell -- https://你的后端入口
# 等价于 VITE_API_BASE=https://... npm run build:shell
```

产物：`miaoda/dist-miaoda/`（`index.html` + `assets/`，约 350 KB）。
`vite.config.ts` 已设 `base: './'`，静态资源用相对路径，挂在子路径下也能加载。

本地想先看效果（不碰妙搭）：

```bash
cd miaoda
npm run dev:web                 # http://localhost:5173，/api 代理到 127.0.0.1:8766
# 目标后端不是 8766 时：$env:OUTFIT_SERVER_ORIGIN='http://127.0.0.1:8765'; npm run dev:web
```

## 5. 传到妙搭

在妙搭工程里选**静态站点/前端应用**，把 `dist-miaoda/` 整个目录作为发布内容（或先打成 zip 再导入）。
如果妙搭要求「构建命令 + 产物目录」而不是直接传文件，等价配置：

| 配置项 | 值 |
| --- | --- |
| 构建命令 | `cd miaoda && npm ci && VITE_API_BASE=https://你的后端入口 npm run build -w @outfit/web`（或仓库根 `npm run build:shell -- <url>`） |
| 产物目录 | `miaoda/apps/web/dist` |
| Node 版本 | 20 或 22 |
| 后端/服务端 | 不需要（纯静态） |

> 妙搭控制台的实际形态（静态托管？自定义构建？能否挂自定义域名？）需要你在控制台确认；上面给的是两种常见形态的对应做法。

## 6. 验收清单

1. 打开妙搭地址 → 出现登录页（不是白屏）。
   - 白屏先看控制台：`Mixed Content` = 后端不是 HTTPS；`CORS` = `cors_origins` 没配或域名不一致。
2. 用现有账号登录 → 顶栏显示「N 个可用模板 · 并发 M」。
3. 小批量试跑：传 1 张定妆图 → 选 1 个场景 → 提交 → 3.5 秒轮询出进度。
4. 历史任务：能看到本机既有记录，定妆图缩略图能显示（说明 `<img src>` 已走绝对地址）。
5. 视频预览/下载能播（说明 `<video>` 与下载链接都带上了后端域名 + 令牌）。
6. 刷新页面仍保持登录（令牌存在 `localStorage['outfit.api_token']`）。
7. 管理端能看到金额（仅管理员）。

## 7. 已知限制

- **同一数据目录只能有一个实例**：妙搭只是前端，后端仍是一份本机进程，不存在抢数据的问题；但别为了套壳再起第二个 `run_web.py`。
- **上传体积**：图片走 base64 JSON（单张 ≤20MB），跨公网隧道时慢；建议隧道开在大带宽线路上。
- **素材检索 tab**：内嵌的是 `http://192.168.10.179:8700` 的 iframe，妙搭页面是 HTTPS → 同样会被混合内容拦掉；需要给素材检索也配 HTTPS，或在套壳版里先隐藏该 tab。
- **画布 tab**：用的是 `canvas/` 的 IIFE 产物，已复制到 `apps/web/public/canvas/`，相对路径加载，正常可用。
- **令牌有效期**：与 Cookie 同口径（`session_hours`，默认 12 小时）；过期后前端会退回登录页。

## 8. 回滚

- 前端：妙搭回退到上一个静态版本即可（后端零改动）。
- 后端：把 `server/web.json` 里的 `cors_origins` 删掉/清空并重启，即恢复「只允许同源」。
