## 1. 修了八件事

### 1.1 登录限流改成 IP 桶 + 账号桶（P1-11）

原来只有一个 key：`client_address[0] + "|" + username`。**换个用户名就是一个新桶**，
永远撞不到上限，等于没限流；配合「未知账号也跑一次 310,000 轮 PBKDF2」，
局域网内 3–5 个并发就能把 CPU 打满，正常提交/轮询一起排队。

现在：

| 维度 | 做法 |
| --- | --- |
| 桶 | `ip|<ip>`（上限 30）与 `user|<账号>`（上限 8）**同时**判定，任一超限即 429 |
| CPU | 登录校验额外加 `BoundedSemaphore(4)`：拿不到槽位直接 429，不排队等哈希 |
| 内存 | 桶用「空桶即删 + 总桶数超 2000 按插入顺序淘汰」，随机用户名刷不出无限增长 |
| 成功登录 | **只清账号桶**。以前两个都清，等于拿自己的合法账号登一次就能把本 IP 的失败计数清零，继续猜别人的密码 |

`LoginLimiter.allowed(key, limit=None)` 新增第二个上限参数；`failed` / `succeeded`
兼容原调用（`tests/test_web_auth.py` 未改一行）。

### 1.2 鉴权失败不读 body、chunked 没有下文（P1-12）

- 未登录分支原来 `return` 了事，请求体一个字节没读。残留字节会被
  `handle_one_request` 当成下一个请求解析（keep-alive 串包）。现在置
  `close_connection = True` 再返回，响应发完即断开。
- `_body()` 只认 `Content-Length`，`Transfer-Encoding: chunked` 以前被当成空 body
  → 解析出 `{}`，请求体留在连接里。现在显式回 **411**（`LengthRequired`），并关连接。

### 1.3 没有 socket 超时、没有并发上限（P1-13）

- `Handler.timeout = 30`（类属性）：`StreamRequestHandler.setup()` 会给 socket
  设读超时。以前发一个 `Content-Length: 32000000` 的头然后不发数据，
  `rfile.read()` 永久阻塞，一条连接占一个线程。
- 新增 `LocalHTTPServer`：`BoundedSemaphore(64)` 限流连接数，超出直接
  `shutdown_request()` 拒绝，不再「再开一条线程陪着等」。

### 1.4 `web.json` 并发写会写坏（P1-14）

`persist_web` 所有线程共用一个 `web.json.tmp`：A 写完被 B 以 `"w"` 截断、
A 先 `replace` 搬走 tmp、B 的 `replace` 抛 `FileNotFoundError`；更坏是交错内容被发布，
下次启动 `load_settings()` 失败 → **全部账号与会话密钥丢失**。

现在：

- 临时文件名带 `uuid4`，`try/finally` 清理，永远不会撞名。
- `WebApplication._web_lock`（**RLock**）串行化写入。
- 五个管理写点（新增/改密/停用/启用/删除账号）改成「改内存 + 落盘」整段持锁——
  否则两个管理员同时改账号时，`json.dumps` 仍可能撞上「字典在迭代时被改大小」。

### 1.5 zip 用固定文件名、边写边发（P1-15）

`tmp/<job_id>.zip` 与 `tmp/batch-<id>.zip` 是固定名：同一任务并发下载会在同一路径上
互相 truncate，客户端拿到 CRC 错误或半截包；`tmp/` 也从不清理。

现在每次请求一个 `uuid` 文件名，发完即删（`try/finally`）。
顺带修掉同一函数里的死代码：`zip_path.stat().st_size == 0` 永远为假
（空 zip 也有 22 字节 EOCD），改成「看真正写进去几个视频」，空包才回 404。

### 1.6 `allow_reuse_address` 写在构造之后（P1-16）

原来在 `ThreadingHTTPServer(...)` 之后才 `server.allow_reuse_address = True`——
绑定早在 `__init__` 里做完了，这行是死代码。

**这里有意偏离评审建议**：评审建议「子类化并设 `allow_reuse_address = False`」。
但在 Windows 上关掉 `SO_REUSEADDR` 后，TIME_WAIT 状态的旧连接会把端口占死，
日常「改完就重启」会频繁报端口占用——代价比它解决的问题更烦人。

所以改成两件事：

- `LocalHTTPServer` 用**类属性**声明 `daemon_threads` / `allow_reuse_address` /
  `request_queue_size`，不再是构造后的死代码；
- 「两个进程同时监听 8765、后起的可能抢到带 Cookie 的请求」改用
  **`web-data/server.lock` 单实例锁**（Windows 用 `msvcrt.locking`，POSIX 用 `flock`）：
  第二个实例启动时直接提示「已有一个网页服务在运行」并退出，比依赖端口语义确定得多。

另外 `访问地址.txt` 的写入挪进 `try/except OSError`：写不了只打印一行，
不再让已经绑好端口的进程退出。

### 1.7 取消打断不了已提交的轮询（P1-17）

`wait_task` 没有停止信号，点取消后已提交的 `max_concurrency` 条会继续轮询到各自超时
（最长 1800s），该用户的批次槽位（`per_user=1`）一直被占，下一单只能排队。

现在：

- `wait_task(..., should_stop: Callable[[], bool] | None)`：检查点在「每次轮询前」
  与「拿到非终态之后」，睡眠按 0.5s 切片（`interval` 默认 15s，整段 sleep 期间
  感知不到取消，取消延迟就是 15s）。命中抛 `WaitStopped`。
- `BatchRunner._submit_and_wait` 传 `self.stop_event.is_set`；`with gate:` 随之退出，
  在飞名额秒级归还。
- 顺带把 `deadline` 从 `time.time()` 换成 `time.monotonic()`（同文件限流器本来就是
  monotonic）：墙钟被 NTP 前跳会让 1800s 的等待提前判死，后跳则等成双倍。

**状态口径**：停止等待的记录落在 `unknown`（`rec["stopped"] = True`），**不是** `canceled`。
因为云端那条任务并没有被取消、可能继续跑完并计费，而 `canceled` 在
`_RETRYABLE_RECORD_STATES` 里——一键「重试失败项」就是二次提交、二次计费。
`unknown` 既不进重试白名单，又会被 `usage_for` 计到失败侧，语义与 P1-2 一致。

### 1.8 queued 取消的竞态（P1-18）

`cancel()` 的 queued 分支只置 `canceled`，不设 `cancel_requested`；而派发线程可能
已经把该 job 放进 `active` 并起了线程。现在一并置 `cancel_requested`，
配合第一批就有的 `_run_job` 开头守卫（`status != "queued"` 或已请求取消即返回），
`finally` 一定把 `active` 槽位还回去。

## 3. 行为变化对照

| 场景 | 之前 | 现在 |
| --- | --- | --- |
| 反复换用户名猜密码 | 每个用户名一个新桶，永不 429 | 同一 IP 累计 30 次失败即 429 |
| 并发提交大量未知账号登录 | 每次 0.1s CPU，可打满进程 | 超过 4 个并发校验直接 429 |
| `Transfer-Encoding: chunked` 的 POST | 当空 body，返回 400/正常处理 | 411 + 关连接 |
| 未登录 POST 带 body | 只回 401，body 残留在连接里 | 回 401 后关连接 |
| 连上不发数据 | 永久占一个线程 | 30s 超时断开 |
| 第 65 条并发连接 | 再开一条线程（无上限） | 直接拒绝 |
| 两个管理员同时改账号 | `web.json.tmp` 互相截断，可能丢全部账号 | 串行化 + uuid 临时名 |
| 同一任务并发下载 zip | 同路径 truncate，半截包 | 各自一个临时文件，发完即删 |
| 启动第二个实例 | 可能静默共用 8765 | 提示「已有一个网页服务在运行」并退出 |
| 点取消 | 已提交的继续轮询到超时（最长 1800s） | 0.5s 内放手，槽位归还 |
| 被停止的那条记录 | 记 `running`，永久不可重试 | 记 `unknown` + `stopped`，提示去控制台核对 |
| 取消排队中的任务 | 极小概率被线程改回 `running` 跑完整批 | 工作线程开头即返回 |

```bash
uv run --no-project --with pillow --with openpyxl python tests/test_web_hardening.py
```
