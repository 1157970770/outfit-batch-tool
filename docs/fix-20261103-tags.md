# 第三批修复记录：标签真源（2026-11-03）

> 基线 `a58646d`（第二批计费修复之后）。对应评审 [code-review-20261103.md](code-review-20261103.md)
> §2.2 的 P1-6 ~ P1-10，即「标签真源可恢复、但不许被静默改写」的五件事。

## 1. 修的五件事

### 1.1 写接口必须带 `revision`（P1-6）

`template_store._mutate` 只在 `revision is not None` 时比对，而 `tag_api` 把
`data.get("revision")` 原样下传——**不传就等于自愿放弃乐观锁**：读一份快照、改完再写回，
中间别人改过的行会被整行覆盖；`restore_version` 甚至能不带 revision 把整库回滚，
与 `tag_api` 开头「旧值写入一律 409」的注释直接矛盾。

现在 `app/web/tag_api.py` 新增 `_revision_of()`，四类写接口一律强制：

| 接口 | 提示语 |
| --- | --- |
| `POST /api/tags/videos/tags` | 改标签需要 revision：请刷新页面拿到最新版本后重试 |
| `POST /api/tags/videos/deprecate` | 弃用/恢复需要 revision：… |
| `POST /api/tags/library`（8 个 action） | 标签库操作需要 revision：… |
| `POST /api/tags/versions/restore` | 回滚版本需要 revision：… |

- `None` / 布尔 → 400；非整数（如 `"abc"`）→ 400「revision 必须是整数」；负数 → 400。
- `TemplateStore.restore_version` 在库层再兜一道：`revision is None` 直接 `StoreError`
  （绕过网页端直接调库也回滚不了）。
- `_mutate` 里 `int(revision)` 的 `ValueError` 转 `StoreError`（400），不再变成 500。
- **豁免**：纯追加的 `upload_video`（走 `add_video`）与 `create_version`（新版本快照）。

### 1.2 导入是合并，不再是整份覆盖（P1-7）

原 `import_from_xlsx` 把 xlsx 解析结果（**在锁外**读的）整份塞进 `self.data["videos"]`，
并且 `_check_import` 只在 `dry_run` 分支里调用：

- CLI `--import-tags` 期间网页上传的视频、别人刚打的标签 → 被静默覆盖；
- 非 dry-run 传一份空清单 → `rows <= 0` 的检查被跳过 → **直接清库**；
- `revision=None`，绕开乐观锁。

现在：

| 项 | 现在 |
| --- | --- |
| 校验时机 | `_check_import(report, allow_empty=...)` 在 dry-run 与真跑**都执行** |
| 空清单 | 抛 `StoreError`「标签清单里没有任何视频行；确认要导入空清单请显式传 `allow_empty=True`」 |
| 重复 id | 不再立刻抛，计入 `duplicate_ids` 由校验统一报错（错误信息带条数） |
| 写入方式 | 按模板 ID 合并：`added` / `updated` / `unchanged` / `kept` |
| 清单里没有的行 | 保留（`kept`），不删、不弃用 |
| 时间字段 | 更新行时跳过 `uploaded_at` / `touched_at`，除非清单给了真值；导入值为空串/0 而现有非空时保留现有值 |
| 标签库 | 旧 tags ∪ 清单 tags；大类顺序 = 旧 order + 内置四类 + 清单里出现过的大类 |
| 清单解析 | 仍在锁外（只读文件），但合并发生在 `_mutate` 的锁内、基于 `_reload_locked()` 后的最新数据 |

返回值新增 `added` / `updated` / `kept` / `unchanged` / `affected`，CLI 直接打印对账。

### 1.3 写盘要真的落盘，失败要真的回滚（P1-8）

原 `_atomic_save` 是 `tmp.write_text(...)` → `os.replace`，全程没有 `flush` / `fsync`；
更麻烦的是 `_mutate`：`fn()` 已经改了内存、`_audit_append` 已经追加，`_atomic_save` 抛错后
**没有快照可回滚**——接口返回 503（用户以为没保存），但此后所有 `snapshot` / `usage` 都读这份
未落盘的「幻影数据」，内存 revision 已 +1 与磁盘分叉，拿着幻影 revision 的客户端下一次写必然 409。

现在：

- `_atomic_save`：`open(tmp, "w", newline="\n")` → `flush()` → `os.fsync(fileno())` → `os.replace`
  → `_fsync_dir()`（POSIX；Windows 目录 fsync 不可用，直接跳过）。
- `_mutate`：`fn()` 之前 `snapshot = (deepcopy(self.data), self._stat)`；写盘失败
  （`except BaseException`）恢复 `data` / `_stat` / 索引后 re-raise → 内存与磁盘一致。
- `changed == 0` 也恢复 snapshot（顺手抹掉 `op()` 可能写进内存的旁支字段，例如 `migrated_from`）。
- `load()`：真源 JSON 坏掉时自动尝试 `.bak`，成功则 `recovered_from_bak = True`，
  否则仍抛 `StoreUnavailable` 并提示「把 X.bak 改回原名后重试」。

### 1.4 xlsx 往返不再丢东西（P1-9）

- **自定义大类**：`save_xlsx` 原来用 `TAG_CATEGORIES` 当白名单，`load_xlsx` 也只在
  四类之内接受分类 → 网页端建的大类 export→import 后全被折叠回第一类。现在两侧都改为
  「任意非空分类」并按首次出现顺序维护 `category_order`，`normalize_tag_categories` 传 `allowed=order`。
- **公式注入**：`ws.append(str(...))` 没把单元格标成文本，openpyxl 会把 `=` 开头的内容写成**公式**；
  回读用 `data_only=True` 拿不到缓存值就是 `None` → 标签/文件名/原始名整个丢。现在
  `load_workbook(..., data_only=False)`，写入时对每个文本单元格设 `cell.data_type = "s"`。

### 1.5 「上传时间」不再是「今天谁改过标签」（P1-10）

模板 xlsx 原来只有 10 列、没有时间列，`load_xlsx` 不产出 `uploaded_at` / `touched_at`，
`_normalize_video` 一路归 0。实测真源 1340 行里 `uploaded_at` **全部为 0**，
其中 1334 行 `touched_at` 也为 0；只有 6 行是当天改过标签的。于是前端「按上传时间排序」
和 72 小时「新」徽标退化成「今天谁动过标签」，这 6 条老视频被顶到最前、戴上「新」徽标。

前端 `app/web/static/tag.js` 现在把两个语义分开：

| 情况 | 排序 | 徽标 | title |
| --- | --- | --- | --- |
| `uploaded_at > 0` | 按 `uploaded_at` | 仅 72h 内为「新」 | 上传于 … |
| `uploaded_at == 0`、有 `touched_at` | 同值段内按 `touched_at` 兜底 | 不出徽标 | 上传时间未记录（最近修改于 …） |
| 两者都 0 | 保持原顺序 | 不出徽标 | 相对路径 |

xlsx 侧补了「上传时间」「最后修改时间」两列（`_iso_time` / `_parse_time`，`<=0` 写空串），
导出的清单带回时间后再导入不会归零，便于以后重建真源时保留历史。

## 3. 行为变化对照

| 场景 | 之前 | 现在 |
| --- | --- | --- |
| 网页保存标签不带 revision | 直接写入（后写者覆盖先写者） | 400，提示刷新后再存 |
| 直接调库 `restore_version` 不带 revision | 整库回滚 | `StoreError`（400） |
| CLI 导入 xlsx（真源已有网页新上传的行） | 整份覆盖，新行消失 | 合并：新行保留，计入 `kept` |
| 导入空清单 | 清库（`rows<=0` 检查被跳过） | 400，除非 `allow_empty=True` |
| 写盘失败（磁盘满） | 接口 503，但内存已有新数据、revision 分叉 | 503 且内存回滚到磁盘状态 |
| 真源被截断（断电） | `StoreUnavailable`，只能手工处理 | 自动读 `.bak` 并标记 `recovered_from_bak` |
| xlsx 里标签是 `=SUM(A1)` | 回读为 `None`，标签丢失 | 原样保留 |
| 网页建的自定义大类 | export→import 折叠回第一类 | 往返不变 |
| 老视频（`uploaded_at=0`）改了标签 | 在「上传时间」里置顶 + 戴 72h「新」徽标 | 不出徽标，title 写「上传时间未记录（最近修改于 …）」 |

## 5. 未纳入本批

- **历史空时间的回填**：1340 行里 `uploaded_at` 全为 0，没有可靠来源（COS 对象头、xlsx 旧列都没有）。
  本批只做「不再把修改时间冒充上传时间」；真要回填，需要用 COS `Last-Modified` 或文件 mtime 做一次显式迁移。
- **`refresh_if_changed` / `_reload_locked` 的 `.bak` 自愈**：只在 `load()` 里做；运行中真源被外部写坏
  仍会抛 `StoreUnavailable`（不静默回退，避免吞掉并发写入）。
- **导入与网页写的一致性**：合并已在锁内、基于最新数据，但 xlsx 解析仍发生在锁外；
  解析耗时（大清单几秒）期间网页的写入不会被丢，只是可能被同样的清单值覆盖。
