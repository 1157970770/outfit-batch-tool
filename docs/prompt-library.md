# 提示词库（分支 `feature/prompt-library`）

> 状态：**未合入主干**。只在分支上工作，`main` 仍然是你现在能跑的那版。
> 目的：把「跑出来效果好、口头说过就忘」的提示词沉淀成可检索的条目，而不是每次都在提示词框里现敲。

---

## 1. 一句话用法

打开程序 → 第三个标签页「提示词库」→ 选场景、勾标签 → 选中一条 → 填变量 → 预览 → **复制** 或 **填入生产页**。

「填入生产页」会同时覆盖「小批量试跑」「大批量生产」两个页面的提示词框，并切回小批量页——因为调提示词该用 3 条试跑，而不是一上来跑 100 条。

---

## 2. 数据存在哪

| 场景 | 路径 |
| --- | --- |
| 源码运行 | `prompts/prompt-library.json` |
| 打包分发 | `exe 同目录\prompts\prompt-library.json`（`sys._MEIPASS` 里也放一份兜底） |
| 临时改一份试 | 环境变量 `PROMPT_LIBRARY=D:\xxx\my.json` |

单文件 JSON：能直接看、能进 Git、备份就是复制一个文件。改完不用重启，点页面右上角**重新加载**即可。

## 3. 一条提示词长什么样

```json
{
  "id": "outfit-closeup-fabric",
  "title": "换装 · 近景面料细节",
  "summary": "模板是近景镜头时用：推近到局部，强调面料纹理与颜色。",
  "scene": "换装",
  "tags": ["近景", "面料质感", "细节特写"],
  "body": "视频1中的{{性别}}模特，镜头推近到{{部位}}，重点展示图1这套服装的{{面料}}纹理与{{颜色}}…"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 缺省由标题生成；重名会自动加序号 |
| `title` | 是 | 列表里那一眼 |
| `summary` | 否 | 一句话说明「什么时候该用它」 |
| `scene` | 是 | 用途场景，单选筛选的维度；缺省归到「未分类」 |
| `tags` | 否 | 自由标签，多选时**要求全部命中**；也接受 `"白底, 特写"` 这种字符串 |
| `body` | 是 | 正文，`{{变量}}` 会被识别 |

顶层的 `scenes` 数组只决定下拉框里的**顺序**；没写的场景按出现顺序追加在后面。

---

## 4. 筛选与变量语义（刻意保持简单）

- **场景**：单选，「全部场景」= 不限。
- **标签**：多选，**同时满足**（`A AND B`），不是"任一"。大小写、首尾空格忽略。
- 结果顺序 = **文件里的顺序**，不是字母序——想推哪条就把哪条写在前面。
- 找不到结果时右栏会提示「去掉一个标签，或把场景切回全部场景」。
- **变量**：正文里写 `{{面料}}`，页面自动生成输入框；库**不存**默认值（这是刻意的：存了默认值，下次就没人改，模板会僵化）。
- 没填的变量**保留占位符**并在预览上方提醒，复制也照旧复制——你能一眼看出哪没填，不会静默给出半成品。

## 5. 加一条提示词

**手改 JSON**（当前唯一方式）：

1. 打开 `prompts/prompt-library.json`，在 `prompts` 数组里加一个对象（字段见上表）；
2. 回程序点「重新加载」；
3. 状态栏会显示加载条数；写坏了不会白屏——单条问题会被跳过并说明原因（缺正文/缺标题/不是对象）。
4. JSON 本身写坏（少逗号、多逗号）时，状态栏直接给**行号**，改完再点重新加载。

> 整份文件坏了也不会影响生产页——只是提示词库这一页停用。

---

## 6. 边界（明确不做的）

- **不写库**：页面只读，没有"新增/编辑/删除"按钮。避免在 UI 里做一套半吊子的编辑器，JSON 手改更快。
- **不改生产逻辑**：不碰 `app/core.py`、不碰 `make_batch.py` 的 `{outfit}` 链路；「填入生产页」只是替你把文本写进提示词框。
- **不做全文搜索**：条目少时场景+标签更快；条数上百再补。
- **不碰授权/分发**：真要随包分发时，这一页的只读属性、以及 JSON 是否该被用户改，需要单独决策（见 §8）。
