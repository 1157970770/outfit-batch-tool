# UI 改版与回滚（界面改版保护）

> 2026-11-02 的界面改版（工作台风格）**不改任何后端逻辑**，只动 `app/web/static/` 下的
> `index.html`、`style.css`、`tag-filter.css`、`batch.css` 和 `app.js` 的少量交互。
> 因此回滚只需还原这几个文件，**不用改配置、不用重建数据、不用动 `web-data/`**。

## 一、基线在哪

| 方式 | 标识 | 说明 |
| --- | --- | --- |
| Git 标签 | `ui-baseline-20261102`（提交 `8283e41`） | 改版前的最后一次提交，含完整前端 |
| 离线快照 | `.backup-ui/20261102/app/web/static/` | 改版前 6 个前端文件的副本，不依赖 Git |
| 改版提交 | 见 `git log --oneline -5` | 改版本身是独立提交，可用 `git revert` 整体撤销 |

前端是**每次请求读盘**，所以还原文件后浏览器 `Ctrl+F5` 即可，**不需要重启服务**。

## 二、三种回滚方式

### 方式 A：只还原前端文件（最常用，推荐）

```bash
cd D:/批量视频任务设计区
git checkout ui-baseline-20261102 -- app/web/static/
```

只把 `app/web/static/` 恢复成基线，后端与其他代码不动。浏览器强刷即可看到旧界面。

### 方式 B：撤销整次改版提交

先找到改版提交：

```bash
git log --oneline -5
```

再整体撤销（会生成一个反向提交，历史保留）：

```bash
git revert <改版提交的 hash>
```

比 `git checkout` 多撤销的只有 `docs/ui-rollback.md` 这类随改版新增的文档，界面效果一样。

### 方式 C：不用 Git（快照覆盖）

```bash
cd D:/批量视频任务设计区
cp .backup-ui/20261102/app/web/static/* app/web/static/
```

适合仓库状态混乱、或改版文件被误删时。这个目录**没有进版本库，别删**。

## 三、回滚后怎么确认

1. 浏览器 `Ctrl+F5`（静态文件有缓存，普通刷新可能还看到新版样式）；
2. 登录页应恢复成旧版：居中卡片、蓝色渐变方块图标；
3. 登录后顶部应重新出现大标题横幅（「把服装图变成换装视频」）；
4. `curl -s http://127.0.0.1:8765/static/style.css | head -1` 应看到旧的单行压缩样式。

## 四、以后再改 UI 的约定

1. 改之前先打一个基线标签，命名统一为 `ui-baseline-YYYYMMDD`：
   ```bash
   git tag ui-baseline-20261103
   ```
2. 顺手做一份离线快照，防止 Git 状态出问题：
   ```bash
   mkdir -p .backup-ui/20261103/app/web/static
   cp app/web/static/* .backup-ui/20261103/app/web/static/
   ```
3. 界面改动单独提交，不要和接口/调度改动混在一个 commit 里——回滚时才能只回退界面。
4. `.backup-ui/` 已在 `.gitignore` 中，不会污染仓库；但它占空间，保留最近 2–3 份即可。

## 五、本次改版到底改了什么（便于判断回不回）

| 方面 | 改前 | 改后 |
| --- | --- | --- |
| 整体风格 | 蓝色主按钮、大圆角（16–22px）、卡片阴影、登录页径向渐变 | 近黑主按钮、6–8px 圆角、无阴影、纯色底；蓝色只用于链接/焦点/运行态 |
| 首页头部 | 营销式大标题（36px）+ 胶囊徽章 | 删除；状态收进顶栏胶囊，标题下放到各页 |
| 顶栏 | 72px，服务状态在页面里 | 56px，状态与账号在同一行；窄屏只留状态点 |
| 信息密度 | 15px 正文、宽松行距 | 14px 正文、13px 控件、表格 12.5px 等宽数字 |
| 交互 | 无 | 记住上次所在页（不含批次页）、`Esc` 关闭任务/账户详情、任务详情加「关闭」按钮 |
| 结构 | — | 视图标题 h2 → h1；`#notice` 移到标签页下方 |

**没有改**：所有接口、字段、权限、调度、限流、金额口径、`web-data/` 数据格式。

## 六、小批量页「控制台」改版（2026-11-02 第二次）

| 方面 | 改前（第一次改版后） | 改后（控制台） |
| --- | --- | --- |
| 布局 | 两列卡片 + 底部确认卡，右列很长要滚动 | **三列控制台**（定妆图 / 场景与参数 / 提示词），高度锁到视口 |
| 横向空间 | 内容宽 1120px，两侧留白大 | 宽度放到 1800px 上限，三列填满，两侧只留 24px 外边距 |
| 滚动 | 1440×900 需要下滑才能看到提交按钮 | **≥1100×680 不出现纵向滚动条**；更小屏自动退回两列/单列并允许滚动 |
| 数量 | 下拉 1/3/5/10 | 分段按钮 **1 / 2 / 3**，单次上限 3 条 |
| 选择方式 | 两个大号单选卡 | 分段控件（自动推荐 / 我来挑选） |
| 画质时长 | 折叠在「更多设置」里 | 直接可见，和数量同面板 |

**上限为什么改 3**：试跑只用于验素材与提示词，`server/web.json → max_job_items` 从 20 调到 3，
改完必须重启；大批量生产不受影响（它走 `max_batch_*`，创建 job 时显式传 `limit_items`）。

### 回退到控制台之前（旧两列页 + 20 条上限）


同时把 `server/web.json` 的 `max_job_items` 改回 `20` 并重启服务。
