# 妙搭迁移方案（React + NestJS）

> 目标：把「换装批量生产器」的**全部功能**迁到飞书妙搭工程（React + NestJS），做到行为等价、数据兼容、可本地开发、可部署上线。
> 本文是总方案 + 进度看板。代码在 [`miaoda/`](../miaoda/)，部署细节见 [miaoda/docs/妙搭部署.md](../miaoda/docs/妙搭部署.md)。

## 1. 为什么要重构，而不是挂静态页

现有前端是 5980 行原生 JS（`app/web/static/*.js`，IIFE + 手写 `getElementById` + `innerHTML` 拼串），后端是 2086 行的 `ThreadingHTTPServer`（`app/web/server.py`）。妙搭工程只认 React + NestJS 的标准产物：

| 现状 | 妙搭要求 | 结论 |
| --- | --- | --- |
| 原生 JS + 无构建 | React 组件 + Vite 构建产物 | 视图必须重写成组件，不能 iframe 挂载 |
| `ThreadingHTTPServer` 手写路由 | NestJS Controller/Module | 接口必须按 Nest 结构重写 |
| 文件系统直接读写 JSON | 后端容器（可持久卷） | 数据目录要可配置、单实例运行 |
| `document.body.append` 弹层、全局 onclick | React 受控渲染 | Portal / props 回调替代 |

因此方案是**双端重写、数据零迁移**：配置继续用 `server/*.json`，数据继续用 `web-data*/*.json`，字段与语义不变，历史任务/批次直接可读。

## 2. 目标架构

```
miaoda/                            npm workspaces（本机无 pnpm，用 npm）
├─ packages/shared/                两端共用的常量与 DTO（状态机、上限、接口形状）
├─ apps/server/                    NestJS 10
│  ├─ src/config/                  读 server/web.json + config.json + imagegen.json（含钳制）
│  ├─ src/auth/                    PBKDF2 校验 / HMAC 会话 / 双桶登录限流 / 全局守卫
│  ├─ src/security/                统一安全头 + Host 白名单 + Origin 校验
│  ├─ src/tags/                    标签真源只读视图（P3 补写入）
│  ├─ src/templates/               提示词库、模板目录（P1/P2 补齐）
│  ├─ src/api/                     Controller（登录、bootstrap、健康检查…）
│  └─ src/main.ts                  全局中间件 + 静态托管 + SPA 回退
└─ apps/web/                       React 19 + Vite 6 + TS
   ├─ src/api.ts                   统一 fetch：JSON、错误体、401 跳登录
   ├─ src/session.ts               /api/bootstrap 一次性装载 user/service/prompts
   ├─ src/App.tsx                  外壳：顶栏 / tab / 视图切换（输出 active-view 类名）
   ├─ src/pages/                   10 个视图（P0 为占位 + 迁移说明）
   └─ src/ui/                      Toast / Placeholder 等共享件
```

前端路由不用 react-router：原版就是 `switchView()` 切 class、不卸载 DOM，且画布的 2500ms 轮询依赖 `#canvas-view.active-view`。`useView()` 复刻同一套语义（切换 + `localStorage['outfit.view']` + hash 同步），并保留 `view` / `active-view` 两个类名。

## 3. 兼容策略（迁移期间两条链路可并存）

1. **配置零改动**：继续读 `server/web.json`（账号、会话密钥、并发上限、`data_root`）、`server/config.json`（Key、模型、COS、单价）、`server/imagegen.json`（生图 Key）。
2. **数据零迁移**：`web-data*/`（生产是 `web-data`，本机开发是 `web-data-dev`）里的 `jobs/*.json`、`batches/*.json`、`template_tags.json` 原样读写；`paths.relocate()` 的「按 `web-data*` 之后的尾部重锚」规则要在 Nest 侧等价实现。
3. **Cookie 同一个名字**：`outfit_sid`，`HttpOnly; SameSite=Lax; Path=/; Max-Age=session_hours*3600`。签名口径逐字复刻：`base64url(JSON{u,r,v,exp})` + `.` + `base64url(HMAC-SHA256(session_secret))`，密钥按 base64url 无填充解。
4. **错误体同构**：一律 `{ok:false,error:"中文文案"}`，前端只读 `error`。
5. **密码哈希可互验**：PBKDF2-HMAC-SHA256 / 310000 轮 / 16 字节盐 / base64url 无填充。已验证「Python 生成 → Node 校验」通过（见 §6）。
6. **状态码对齐**：登录/登出是 200（Nest 的 POST 默认 201，已用 `@HttpCode(200)` 修）；未知路由 404、Host 不合法 421、Origin 不合法 403、chunked 411。

## 5. P0 已交付内容

**后端**（`apps/server`）

- 配置服务：读取三份 JSON，字段钳制与 `settings.py` 一致（`max_active_jobs` 1..20、`max_job_items` 1..100、`small_lane_items` ≤3、`small_lane_inflight` 1..50 等），缺 `session_secret` 直接报错并提示先跑 `python run_web.py --init`。
- 鉴权：`makePassword/verifyPassword` 走 **异步 pbkdf2**（310k 轮同步会卡死事件循环，调度线程也在同一进程）；`LoginLimiter` 双桶（IP 30 次 / 账号 8 次，10 分钟窗口）；登录并发闸门 4；未知账号也 burn 一次哈希抹平时序；成功只清账号桶。
- 安全中间件：`Cache-Control: no-store`、`nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、CSP（`frame-src` 放行素材检索地址）；Host 白名单（含本机全部网卡 IPv4）；POST/DELETE 的 Origin 协议+主机校验；`Transfer-Encoding: chunked` 直接 411。
- 接口：`POST /api/login`、`POST /api/logout`、`GET /api/me`、`GET /api/bootstrap`、`GET /healthz`。
- 静态托管：`apps/web/dist` 存在时托管 + SPA 回退（`/api/*` 与带扩展名的路径不吞）。

**前端**（`apps/web`）

- React 19 + Vite 6 + TS，`@/` 别名、`@outfit/shared` 直连源码。
- 外壳：登录页（错误文案直出）、顶栏（开发版标记、模板数、并发）、9 个 tab（管理仅管理员）、视图切换保留 `active-view`。
- 统一请求层：`api()` 带 `credentials: same-origin`、统一错误体解析、401 时由 `session.ts` 注册的处理器回登录页。
- Toast 单例：后到覆盖、3200ms，与旧版一致。
- 占位页写明该页在哪个阶段迁移、要满足哪些交互，迁移进度在界面上可见。

**工程化**

- `npm run dev`：先编 `packages/shared`，再并发 `nest start --watch`（3001）+ `vite`（5173，代理 `/api`、`/healthz`）。
- `npm run build`：shared → server（`nest build`）→ web（`vite build`）。
- `node scripts/parity.mjs [base]`：23 项离线断言（见下）。

## 6. P0 实测结果（2026-11-10）

用「Python 生成密码哈希 + 专属 server 目录」起了一个隔离实例（端口 3101，`OUTFIT_SERVER_DIR=miaoda/.tmp/parity/server`，数据仍读 `web-data-dev`）：

```
[1] 基础探活            /healthz 200；带 version=0.20.0 与 dev
[2] 未登录语义          /api/me 401 + {ok:false,error:"登录已过期，请重新登录。"}
[3] 安全头与校验        no-store / DENY / CSP frame-ancestors none / 未知 Host 421 / 未知 Origin 403
[4] 登录               错误密码 401「账号或密码不正确。」；正确密码 200；
                       Set-Cookie: outfit_sid=…; Path=/; HttpOnly; SameSite=Lax; Max-Age=43200
[5] 会话与 bootstrap   /api/me 200；bootstrap 的 templates_count=1159、max_images=10、
                       produce_choices ⊆ [5,10,20,50,100]、prompts 5 条且不含 p01
[6] 登出               200 + Max-Age=0
结果：23/23 通过
```

另外验证：`/` 与 `/some/deep/link` 都返回 `index.html`（SPA 回退），`/assets/index-*.js` 返回 `application/javascript`；vite 5173 代理 `/api` → 3001 通。

> **关键结论**：现有 `server/web.json` 里的账号密码哈希（Python 生成）在 NestJS 侧能直接校验通过，说明会话/密码口径完全兼容——迁移不需要重置任何人的密码。

## 7. 关键技术决策

| 决策 | 理由 |
| --- | --- |
| 新建 `miaoda/` 而不是改造现有工程 | 生产运行区只允许 `git pull`，Python 链路必须随时可回退；两套并存才能灰度 |
| npm workspaces（非 pnpm） | 本机没有 pnpm；npm 10 的 workspaces 足够，少一个前置依赖 |
| 后端全量重写而非包一层 | 妙搭要求 NestJS 结构；包一层 `server.py` 会同时背上 Python 运行时与两套鉴权 |
| 密码校验用异步 pbkdf2 | 310k 轮同步约 100ms+，会阻塞登录并发与任务轮询 |
| 前端不用 react-router | 原版不卸载 DOM、靠 class 切换；画布轮询读 `#canvas-view.active-view`，语义必须一致 |
| 保留 `view`/`active-view` 类名 | 现成 CSS 的 `#create-view.active-view` 等选择器直接可用，减少视觉回归 |
| 占位页写清阶段与交互 | 迁移期由人接手时，界面即进度看板，避免「看起来能点但没实现」 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Windows 沙箱下 esbuild 起不来（`spawn EPERM`） | `vite build` / `vite dev` 失败 | 构建时放宽沙箱或在普通终端跑；`npm install --ignore-scripts` 可绕过 postinstall 阶段的 EPERM |
| 轮询三套节奏（3500/4000/2500ms） | 迁移后互相打架、请求翻倍 | 统一 `useVisiblePolling`：可见 + 页面激活 + 有在飞任务才跑 |
| 画布单 root | 二次 `createRoot` 会报错 | 包装组件 mount 调 `CanvasUI.enter()`、unmount 调 `leave()`；不新建 root |
| 事件委托 → 受控组件 | 槽位的 `root.onclick` 是覆盖式赋值 | 改成 props 回调；槽位状态机（idle/uploading/done/error）保留 |
| CSS 冲突 | `.drop-zone`/`.slot-*`/`.tag-*` 跨文件复写，`.hidden` 被 `display:grid` 覆盖 | 按页迁入并加作用域；先保 id 选择器与类名不变，再逐步收敛 |
| 数据绝对路径 | 换机器/换目录后 `out_path` 悬空 | 移植 `paths.relocate()`：按 `web-data*` 之后的尾部重锚，找不到就原样返回 |
| 单实例约束 | 两个进程争抢 jobs 文件 | 文档写明单实例；后续可加 data_dir 实例锁（Python 版已有） |

**前端**

- `pages/TagPage.tsx`：三态筛选、表格分页（50/100/200）、批量打标/评分/弃用（弃用前先 `impact` 查未完成批次）、编辑模态、标签库抽屉、版本抽屉、上传模态；写路径统一带 `revision`，冲突自动重拉快照。
- `pages/AdminPage.tsx`：状态卡、模板健康、账户用量（金额只在这里出现）、归档检索与签名、用户增删/配额/重置。

**实测结果**

- `scripts/p3-smoke.mjs`：改标签（`revision` +1）→ 旧 `revision` 409 → 缺 `revision` 400 → `impact` 含 `locked_batches` → 弃用/恢复 → 评分 → 库操作（`confirm_required`）→ 版本列表/手动快照 → 管理端全部接口（users 返回里断言没有 `hash`）→ 新增账号/重复 409/配额/重置/停用后登录 401 → 明细/CSV/删除，**39/39 通过**。
- 兼容性：直接读 Python 写的 901KB 真源（schema=3、revision=2070、1457 条视频、30 个标签、5 类）与 gz 版本快照均正常。

**已知限制**

- Python 的 `msvcrt` 文件锁与 Node 的目录锁**互不识别** → 同一 `data_dir` 不能混跑两种实现，灰度必须复制数据目录。
- 视频上传的 COS 落盘未接：只登记清单并回 `warning`，不伪造 `key/url`。

## 15. P5 服务端收尾现状（2026-11-11）

NestJS 侧补齐了 Python 版里「上线才会踩到」的四块基础设施：

| 能力 | 实现 | 验证 |
| --- | --- | --- |
| 单实例锁 | `common/instance-lock.ts`：`<dataDir>/server.lock.d` 原子目录锁 + 15s 心跳；PID 不存在或心跳超 90s 视为陈旧可接管 | 5 项单测；同数据目录起第二个进程 `EXIT=2` 且打中文提示 |
| 权限隔离 | 复用 Python 的 owner 口径：`?scope=all` 仅管理员，任务/批次按 owner 校验 | `scripts/p5-roles-smoke.mjs` **23/23**（含 B 读/取消 A 的任务 403） |
| COS 适配器 | `storage/cos-client.ts` 手写 v5 签名（PUT/GET 带 Range/HEAD/DELETE/列举/预签名）；`storage/storage.service.ts` 提供 `objectKey()`（与 `app/storage.py` 同口径）、`fingerprint()`、`putFile/putBuffer/getObject/signUrl/listPrefix` | 7 项单测（签名参数、Key 规则、指纹稳定性）；**未真连桶** |
| 归档与上传 | 任务成片归档到 `{prefix}/output/<日期>[/款号]/<批次>/<名>-<指纹>.mp4`（记 `cos_key`/`cos_url`，失败记 `archive_error` 不影响成片）；视频库上传写 `input/tpl/` + `manifest_overlay.json`；自由视频参考视频/音频写 `videogen/ref/` 后给 7 天预签名 URL | tsc 0 错、server 156 项单测全绿；COS 关闭时全部走降级分支（不报错） |

**仍然欠账**：① 真实 COS 端到端（上传 → 预览 → 归档 → 预签名下载，会往桶里写对象，需你点头再跑）；② 双桶限流/在飞名额压测（真 Key 上跑才算数）；③ 视觉回归（本机没有浏览器截图工具）；④ 妙搭控制台的构建/持久卷/端口注入三个问题。
